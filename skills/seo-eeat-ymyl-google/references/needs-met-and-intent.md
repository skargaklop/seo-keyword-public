# Needs Met And Intent

## Когда нужен `Needs Met`

Применяй только если есть query context:

- отдельный запрос;
- query cluster;
- понятный пользовательский intent.

Если запроса нет, ставь `N/A` и не смешивай usefulness с `Page Quality`.

## Базовые типы интента

- `Know` / `Know Simple`: пользователь хочет понять факт, концепт или ответ.
- `Do`: пользователь хочет совершить действие, транзакцию, регистрацию, скачивание.
- `Website`: пользователь ищет конкретный сайт или страницу.
- `Visit-in-person`: нужен локальный офлайн-результат.

## Шкала `Needs Met`

- `ПС`: практически идеальное попадание для однозначного intent.
- `ВС`: очень полезный результат для основного intent.
- `СС`: помогает, но не лучший и не исчерпывающий.
- `НС`: лишь частично закрывает intent.
- `ОС`: не решает задачу пользователя.
- `N/A`: нет query context.

## Практические правила

- Высокий `Page Quality` не гарантирует высокий `Needs Met`.
- Слабая страница может случайно отвечать на узкий запрос, но это не делает ее качественной.
- Для `Know Simple` особенно важны краткость, точность и answer-first pattern.
- Для `Do` важны trust, ясность шага и безопасность транзакции.
- Для `Website` лучший результат обычно официальный или целевой URL.
- Для `Visit-in-person` учитывай локальность, контакты, часы, адрес и релевантность локации.
